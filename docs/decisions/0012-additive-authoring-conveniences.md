# ADR 0012 — Additive authoring conveniences

Status: accepted by the project owner on 2026-11-18 as additions on the `ergonomic-refactor` branch. No existing API is removed or changed.

Decision: four additions shorten authoring without moving any check from compilation to run time and without changing initialization.

`(*Node).Virtual[T any]() T` and `(*Node).Parent[T any]() T` resolve through the holder's stored scope and the existing resolver; they are equivalent to `Method[T](n.Scope())` and `ParentMethod[T](n.Scope())`. A nil `*Node` receiver panics with a typed `Uninitialized` error carrying the requested capability. `Method`, `ParentMethod`, `Scope`, and `Node.Scope` are unchanged. The documented call form goes through the provider's own directly declared holder field by its actual name: `receiver.Node.Parent[T]()`, or `receiver.Dispatch.Parent[T]()` when the holder is embedded under the alias name `Dispatch`. Go also permits the promoted spelling `receiver.Parent[T]()`. It is not used in examples, because an application field or method of the same name can make it fail to compile, and an application generic method of the same name and shape silently replaces it.

`(*LevelHandle[Leaf]).BindNode[Operation any](witness Operation)` and `(*LevelHandle[Leaf]).BindNodeGroup[Provider any](witness *Provider, operations ...OperationToken)` are `Bind` and `BindGroup` with the provider path fixed to `"."`. They keep the same compile-time and validation-time checks, sticky diagnostics, duplicate and coverage rules, and freezing behavior.

`(*Definition[Leaf]).Extend[Node any]()` appends a level that inherits the preceding level's effective public and private contracts. `(*Definition[Leaf]).ExtendWith[Node, Public, Private any]()` appends a level with the given contracts. Both infer the parent edge as the single direct anonymous value field whose type equals the preceding level's node type; validation records that field's declared name, including an alias name, in the validated metadata. No candidate or more than one candidate is `InvalidHierarchy`, and the author then uses `Level` with an explicit field name. Both methods require a preceding level: called first on a definition, they record a sticky `InvalidDeclaration`, add no level, and return an inert handle, as the owner decided. After preparation they behave as `Level` does. The root is still declared through `Level`, which is unchanged.

`LevelHandle` exposes the definition's operations: `Level`, `Extend`, `ExtendWith`, `Validate`, `Prepare`, `MustPrepare`, `Init`, `MustInit`, `NodeProvider`, and `ComponentProvider`. Each forwards to the same underlying definition, so `End` is optional and unchanged. Registrations through a saved handle still affect its original level; a level added through any handle is appended to the end of the definition's chain. The handle's definition reference stays unexported.

Not adopted in this decision: bare-pointer or implicit-leaf initialization, slot inference from a provider pointer, witness-free registration, optional or variadic path and parent arguments, removal of any existing form, and code generation. `Init`, `ProviderRef`, `NodeProvider`, and `ComponentProvider` keep their signatures, lineage, slot claims, ownership checks, and diagnostics.

Alternatives: an interface accepting any holder-bearing receiver could not restrict its arguments to valid providers, because method promotion lets embedded pointers and embedded interfaces satisfy it; free functions taking `*Node` add no promoted spelling but save little; variadic optional arguments would turn an arity compile error into a run-time rejection. None is selected.
