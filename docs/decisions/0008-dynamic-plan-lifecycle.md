# ADR 0008 — Dynamic Plan preparation and instance binding

Status: accepted by the project owner for M5. Grouped registration was later approved in [ADR 0009](0009-grouped-fluent-registration.md), and concurrent preparation and precomputation in [ADR 0010](0010-concurrent-preparation-and-precomputed-plans.md). Component factories remain open.

Decision: `Definition[Leaf]` has `Prepare() (*Plan[Leaf], error)`, `MustPrepare() *Plan[Leaf]`, `Init(*Leaf, ...ProviderRef[Leaf]) error`, and `MustInit(*Leaf, ...ProviderRef[Leaf]) *Leaf`. A prepared `Plan[Leaf]` has the same Init/MustInit pair. Both Definition and Plan have a generic `NodeProvider[Node any](*Node) ProviderRef[Leaf]` method. ProviderRef and Plan have unexported fields. Must operations panic with the error from their underlying operation; successful MustInit returns the original leaf pointer.

A definition-created reference carries declaration lineage, node-type identity, and the supplied pointer without preparing or freezing. Init resolves its slot against the prepared Plan; a type or lineage match alone does not establish physical ownership. Plan-created references use the same lineage. Future resolution variants from that definition accept the same references; independently declared definitions do not. Reference factories never record sticky definition errors. An unusable factory receiver or invalid pointer yields an invalid reference for Init to reject with a typed error. A nil or unprepared Plan's Init returns InvalidPlan; its MustInit panics with that error.

Successful preparation validates one snapshot, builds complete immutable receiver-free dynamic metadata, freezes the definition, and publishes the Plan. Repeated preparation reuses it without revalidation, unless a rejected edit has been recorded. A post-freeze Level or Bind call leaves the metadata and Plan unchanged and records sticky InvalidDeclaration. Rejected Level returns an inert handle: chained Bind adds nothing and End returns the original definition. Later Validate, Prepare, or definition-based Init reports that sticky error, while a retained Plan remains usable. Saved valid level handles stay attached to their levels but cannot edit them after freezing.

Failed preparation publishes no Plan and leaves the definition editable, subject to existing sticky declaration diagnostics. Failed instance initialization leaves every scope unchanged and keeps successful preparation available. Every Init checks its own leaf and provider references; successful initialization retains only the necessary receivers in that object's dispatch binding, never the caller's mutable reference slice. Plans and preparation diagnostics retain no application object, Node holder, scope, bound method, object-capturing closure, or instance-bearing reference. Prepared Plan operations do not consult mutable definition state or serialize independent object initialization. Concurrent first-use coordination remains outside this decision.

Implementation reuses the M3 validators and typed dispatch kernel. Preparation obtains validated metadata once rather than calling Validate and repeating validation. Shared types, contracts, paths, capability identities, and registration layout live in the Plan; actual receivers, holder checks, bindings, and scopes remain per instance. M5 requires one node reference per level, keyed by distinct named node type. The reference representation can later distinguish component slots within a level without changing Init; exact component factories and their reflection integration remain undecided.
