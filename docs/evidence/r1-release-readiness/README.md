# R1 evidence: release-readiness fixes

Raw outputs behind the [R1 roadmap entry](../../roadmap.md#r1-release-readiness-fixes), recorded on 2026-11-20 on the `release-readiness` branch with Go 1.27.1 on darwin/arm64 (Darwin 25.5.0), by local scripts, not by GitHub Actions. No remote CI run is recorded here. R1 is uncommitted in the working tree over `9b738c0`.

`replay-gates.sh` is a copy of the G1 script in [private-probe-alias/](../g1-generator/private-probe-alias/replay-gates.sh): it runs every Go step of the CI workflow except the fuzz step, prints each command with its exit status, and exits 1 if any step fails. `docs-checks.sh` does the same for the documentation checks. `record.sh` started as a copy of the [G1 recorder](../g1-generator/private-probe-alias/record.sh) and no longer matches it. It runs one command and writes its output after a header with the time, the toolchain, the system, the commit and state of the tree, a fingerprint of every file outside `docs/` taken before and after the run, and the command's exit status. In the second review follow-up the header also gained the recorded command and each uncommitted path outside `docs/`, with its git status and SHA-256 at the start of the run, so a reader can tell exactly which files a run's tree held.

The records made before that change are the four Red records, `part1-red.txt`, `part2-red.txt`, `holder-path-red.txt`, and `uninitialized-level-red.txt`. They identify their trees by fingerprint only, so those trees cannot be reconstructed from them. They are kept as they were recorded.

No Green is kept on its own. The Greens of Part 1 and Part 2 were not saved separately. The holder path Green was saved at first and then replaced; it is not kept separately. The two-holder tests' first run, the first run of the single-level AlreadyInitialized message row, and the Green of the Uninitialized level fix were not saved. The final focused run in `focused.txt` runs every R1 test on the final tree and supersedes them all.

After the second review follow-up, the stated reason for rejecting unexported alias holders was corrected at the owner's direction, as item (d) of that follow-up in the roadmap records. One of the three corrections is a comment in `hierarchy.go`, which changed the source fingerprint, so `focused.txt`, `gates.txt`, `fuzz.txt`, and `docs-checks.txt` were recorded again on the resulting tree.
